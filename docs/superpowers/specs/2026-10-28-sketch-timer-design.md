# Таймер набросков — техническая спецификация

Продуктовые требования: `docs/product.md`. Здесь закрыт раздел «Остаётся разработчику».

## 1. Стек и структура

- **Electron + TypeScript**, интерфейс на React + Vite (renderer), главный процесс на Node.
- **SQLite через встроенный `node:sqlite`** (без нативных модулей: нет проблем с ABI Electron/Node, одна и та же база в тестах и в приложении). Требует Electron с Node ≥ 22.13.
- Тесты: **Vitest** для всей логики (ядро не зависит от Electron), Playwright (Electron) для одного дымового теста интерфейса.
- Сборка: **electron-builder, target `portable`**; .exe собирается в GitHub Actions (windows-latest). Локально в Linux проверяются тесты, типы и сборка renderer.

Разделение на модули (каждый тестируется отдельно, без Electron):

| Модуль | Назначение |
|---|---|
| `core/db` | подключение, миграции (`PRAGMA user_version`), репозитории |
| `core/library` | сканирование папок, дерево категорий, сверка при запуске |
| `core/rename` | безопасное переименование |
| `core/picker` | построение очереди сессии, веса |
| `core/timer` | развёртывание пресета в шаги, конечный автомат сессии |
| `core/backup` | экспорт/импорт |
| `main/` | окно, IPC, путь данных, обработка ошибок записи |
| `renderer/` | экраны: библиотека, избранное/дизлайки, пресеты, настройка и сессия |

## 2. Данные (SQLite)

Файл `sketch-timer.db` лежит в папке с .exe (`PORTABLE_EXECUTABLE_DIR`, в разработке — `./data`).

- `settings(key, value)`: путь библиотеки и т.п.
- `categories(id, parent_id, name, rel_path)`: корневые папки — категории, вложенные — подкатегории.
- `images(id, category_id, rel_path, file_name, rating, size, mtime, missing)`: `rating` ∈ {0, 1 лайк, −1 дизлайк}; `rel_path` — относительно корня библиотеки; `missing=1` вместо удаления записи, если файл пропал (оценки не теряются).
- `views(id, image_id, cycle, completed_at)`: завершённые просмотры. Цикл категории — это номер цикла, а не удаление истории.
- `presets(id, name, description)`, `preset_groups(id, preset_id, position, repeats, work_label, work_sec, rest_sec)`; группа без отдыха: `rest_sec = 0`; «Приготовьтесь» — группа с `repeats=1`, `rest_sec=0`.
- `sessions(id, started_at, ended_at, preset_id, state_json)`: состояние для прогресса и навигации.

## 3. Форматы изображений

Поддерживаются то, что декодирует Chromium: `.jpg .jpeg .png .webp .bmp .avif`. GIF (`.gif`) игнорируется при сканировании. Прочие расширения пропускаются. Определение по расширению без учёта регистра. Файл, который не открылся, помечается как битый и не попадает в очередь (сессия не падает).

## 4. Сканирование и обновление

- Первичное подключение: рекурсивный обход, построение дерева, индексация, затем переименование.
- Сверка при каждом запуске и по кнопке «Обновить»: сравнение диска и БД (новые добавляются, пропавшие получают `missing=1`, вернувшиеся снимаются).
- Слежение в реальном времени (`fs.watch`) не делаем: YAGNI, сверки при запуске и по кнопке достаточно.

## 5. Переименование

Шаблон `{родительская_папка}_img_{NN}`, нумерация от 01, ширина минимум 2 цифры (при >99 — шире).

- Новые файлы получают следующий свободный номер в своей папке: максимум существующих номеров по шаблону + 1, и проверка, что целевого имени нет на диске.
- Уже переименованные (имя по шаблону для этой папки) не трогаются. Расширение сохраняется.
- **Никогда не перезаписывать**: используется `rename` только если целевого имени нет (проверка `lstat`), иначе берётся следующий номер. При пересечении имён (A→B, B→A) применяется двухфазное переименование через временные имена.
- Ошибка одного файла не прерывает остальные, итог показывается списком. Запись в БД обновляется после успешного `rename`.
- Автоматически при импорте новых файлов и вручную кнопкой «Переименовать».

## 6. Выбор изображений

- Пул сессии: изображения выбранных категорий (включая подкатегории), `rating != −1`, `missing=0`, не битые.
- Для каждой категории: непросмотренные в текущем цикле. Если их не осталось, номер цикла категории увеличивается и в пул возвращаются все.
- Порядок: **взвешенная случайная выборка без возвращения** (Эфраимидис–Спиракис: ключ `u^(1/w)`), вес обычного = 1, **лайк = 3**. Вес вынесен в константу.
- Внутри сессии повторов нет. Если пул исчерпан раньше, чем закончилось расписание, начинается новый цикл (повторы возможны только после полного обхода).
- Просмотр записывается в `views` только по окончании рабочего интервала. Пропуск вперёд не записывает. Шаг назад возвращает предыдущее изображение и откатывает счётчик на один шаг; запись `views` за тот шаг, если уже была сделана, удаляется.

## 7. Таймер

Пресет разворачивается в линейный список шагов: `work(label, sec, imageSlot)` и `rest(sec)`. Конечный автомат: `idle → running ↔ paused → finished`. Время отсчитывается по монотонным часам (`performance.now`), а не накоплением тиков, чтобы не уходить.

- Конец работы: запись просмотра, переход к отдыху (изображение остаётся или затемняется), затем следующее изображение и следующий рабочий интервал.
- Конец расписания: экран итога. Прогресс сверху: пройдено / всего рабочих интервалов.
- Ручной переход вперёд/назад начинает рабочий интервал нового изображения заново. Отдых при ручной навигации пропускается.
- Пауза замораживает отсчёт.

## 8. Экран сессии и управление

Полноэкранное окно, изображение по центру (`object-fit: contain`), справа сверху таймер и название упражнения, ниже кнопки, сверху полоса прогресса. Тёмная тема.

Клавиши: `Пробел` пауза/продолжить, `→` вперёд, `←` назад, `L` лайк, `D` дизлайк (повторное нажатие снимает оценку), `Esc` завершить (с подтверждением).

## 9. Резервная копия и импорт

- Экспорт: файл `.sketchbackup.json` (версионированный: `format: 1`) с оценками, пресетами и (по выбору) историей просмотров. Также можно скопировать сам `.db`.
- Импорт переносит только оценки и пресеты. **Сопоставление изображений**: сначала по `rel_path` + имя, затем по размеру файла + имени; изображения без совпадения сообщаются в итоговом отчёте и пропускаются. Пресеты с совпавшим именем импортируются как копия «(импорт)», ничего не перезаписывается.

## 10. Ошибки

- Папка приложения недоступна для записи: на старте проверка записью временного файла; при неудаче диалог с понятным текстом на русском и путём, приложение закрывается (без молчаливого запуска в другом месте).
- Библиотека недоступна (диск отключён): экран с предложением выбрать папку заново, данные не удаляются.

## 11. Тесты (TDD)

Vitest: picker (веса, без повторов, цикл, дизлайки), timer (развёртывание, пауза, навигация, прогресс), rename (коллизии, обмен имён, идемпотентность, расширения), library (GIF, сверка, missing), backup (экспорт/импорт, сопоставление), db (миграции). Дымовой тест Electron запускается в CI.

## 12. Вне объёма первой версии

Автоопределение сложности, облако, редактирование изображений, слежение за файловой системой в реальном времени, GIF.
